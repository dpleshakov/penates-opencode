## Deliverables

The boundary here is the text's destiny, not its container: whether it will stay in the
repository or go outward — or live only inside this conversation. What enters code, git
history, or other people's hands is a deliverable. What exists for agreement and travels
no further is chat speech. Saving such text into a file (including `.md`), or wrapping
it in the English-language mechanics of a tool — headers, mode prompts — does not promote
it into a deliverable.

Text artifacts default to `.md`; `.html`, `.pdf`, `.docx` — only on request.

### Project conventions

Defaults yield to project convention: if the project writes its artifacts differently,
new ones follow the project.

### Deliverable register

The register of deliverables — text that goes into the repository or outward — is set by
the `writing` skill, and the liveliness from chat does not carry over there.
